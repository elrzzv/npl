# Задача 1.2 — банковские переводы через STM (Haskell)

## Запись с демонстрацией
https://drive.google.com/file/d/1Hl5cZfAq6Z7ydzWUQ7Oi3OEJuixp1qdc/view?usp=drive_link

## Постановка задачи

8 счетов хранятся в `TVar Int`. Четыре потока выполняют по 20 000 попыток
случайного перевода на сумму от 1 до 200. Каждый перевод — одна транзакция
`atomically` с `readTVar`/`writeTVar`.

Переводы на тот же счёт и при нехватке денег пропускаются, поэтому
80 000 попыток не означают 80 000 выполненных переводов. После завершения
потоков проверяются сохранение общей суммы и отсутствие отрицательных
балансов.

## Требования

* GHC, доступный командой `ghc` в терминале (проверено с GHC 9.10.3).
* Библиотеки `base`, `stm` и `time`, поставляемые с проверенной версией GHC.
  Дополнительные пакеты, Cabal-проект и расширения редактора не нужны.

Если GHC ещё не установлен, его можно установить через
[GHCup](https://www.haskell.org/ghcup/). Каталог `bin` GHCup должен быть
в `PATH`; после изменения `PATH` откройте новый терминал.

## Сборка и запуск

Из корня репозитория в PowerShell:

```powershell
cd ./1_task_2_haskell
ghc -O2 -threaded -rtsopts -o Main.exe Main.hs
./Main.exe +RTS -N4 -RTS
```

`-O2` включает оптимизацию, `-threaded` подключает многопоточный runtime,
а `-rtsopts` разрешает передавать ему параметры при запуске.
`+RTS -N4 -RTS` задаёт четыре возможности параллельного исполнения
(capabilities) для потоков Haskell; потоки создаются в коде через `forkIO`.

Ожидаемый итог: `CHECK: sum unchanged, balances non-negative -- OK`.
Начальные числа и итоговые балансы меняются от запуска к запуску.
При нарушении проверки программа завершится с ненулевым кодом.
