# NL_2026

Индивидуальная работа: 20 программ на 20 разных языках программирования.
Пять тем, на каждую тему — по 4 программы. Специализированные библиотеки не используются.

## Порядок работы

Каждая задача делается в отдельной ветке. Имя ветки: `<номер темы>_task_<номер задачи>_<язык>`,
например `1_task_1_ada`. Исходники лежат в папке своей темы: `<папка темы>/task_<номер>_<язык>/`.

## Тема 1. Многопоточность

Папка: `1_threads/`

| № | Задача | Язык | Ветка |
|---|--------|------|-------|
| 1 | Параллельная факторизация чисел пулом worker-процессов | Scala | `1_task_1_scala` |
| 2 | Банковские переводы между счетами через STM | Haskell | `1_task_2_haskell` |
| 3 | Параллельный рендер фрактала Мандельброта в PPM | Julia | `1_task_3_julia` |
| 4 | Параллельный обход дерева каталогов с подсчётом статистики | Groovy | `1_task_4_groovy` |

1.1 **Scala.** Программа генерирует список из 100 случайных чисел в диапазоне от 2 до $10^{12}$. Создаётся пул из 4–8 worker-потоков через java.util.concurrent.Executors.newFixedThreadPool. Каждое число оборачивается в задачу Callable, которая перебирает делители до $\sqrt{n}$ и возвращает факторизацию в виде списка пар «простое число — степень». Задачи отправляются в пул через ExecutorService.submit, результаты собираются через Future.get. Главный поток дожидается всех результатов, печатает каждое число, его факторизацию и общее время работы. Дополнительно запускается последовательная версия на одном потоке, чтобы сравнить время с параллельной.

1.2 **Haskell.** Есть N счетов, представленных TVar. Несколько потоков одновременно делают случайные переводы между счетами. Каждый перевод выполняется внутри atomically с writeTVar. После завершения всех потоков программа проверяет, что сумма всех балансов не изменилась.

1.3 **Julia.** Программа генерирует изображение фрактала Мандельброта, например 800×600. Строки или блоки изображения распределяются между потоками через Threads.@threads. Каждый поток считает свою часть и пишет пиксели в общий массив, не пересекаясь по индексам. В конце изображение сохраняется в формат PPM. Дополнительно выводится время для 1 потока и для N потоков.

1.4 **Groovy.** Программа принимает путь к каталогу. Сначала рекурсивно собирается список всех подкаталогов в ConcurrentLinkedQueue. Затем запускается N потоков (Thread), которые берут подкаталоги из очереди, обходят файлы в них и складывают статистику в общие ConcurrentHashMap: количество файлов по расширениям и суммарный размер. Для суммарного размера используется AtomicLong. В конце печатается топ-10 расширений по количеству файлов, общий размер и время работы для 1 и N потоков.

## Тема 2. Алгоритмические задачи

Папка: `2_algorithms/`

| № | Задача | Язык | Ветка |
|---|--------|------|-------|
| 1 | Обход бинарного дерева в порядке in-order без рекурсии и с рекурсией, сравнение | OCaml | `2_task_1_ocaml` |
| 2 | Генерация всех перестановок строки с отсечением дубликатов | Scheme | `2_task_2_scheme` |
| 3 | Нахождение наибольшей общей подпоследовательности двух строк | Rust | `2_task_3_rust` |
| 4 | Раскраска графа минимальным числом цветов (бэктрекинг, рекурсия) | Prolog | `2_task_4_prolog` |

2.1 **OCaml.** Строится бинарное дерево поиска из списка чисел. Сначала выполняется рекурсивный in-order обход, который печатает элементы в отсортированном порядке. Затем тот же обход реализуется итеративно с явным стеком. Оба результата сравниваются, печатается время работы каждого варианта на дереве из ~100 000 узлов.

2.2 **Scheme.** На вход подаётся строка, например "aabc". Рекурсивная функция строит перестановки: на каждом шаге выбирается один символ, оставшаяся часть переставляется рекурсивно, результаты склеиваются. Дубликаты отсекаются через список уже найденных перестановок: новая перестановка добавляется только если её ещё нет в списке (проверка через member). Выводятся все уникальные перестановки и их количество. Дополнительно сравнивается с "abc" — там дубликатов нет.

2.3 **Rust.** Даны две строки. Строится матрица DP размера $(n+1)×(m+1)$, где $dp[i][j]$ — длина LCS префиксов. Затем обратным проходом восстанавливается сама подпоследовательность. Печатается длина, сама LCS и время работы.

2.4 **Prolog.** Граф задаётся фактами edge(a, b). — неориентированные рёбра. Нужно найти минимальное число цветов k, при котором можно правильно раскрасить все вершины так, чтобы соседние вершины имели разные цвета, и вывести одну такую раскраску.

## Тема 3. Ввод/вывод в консоль и файл

Папка: `3_io/`

| № | Задача | Язык | Ветка |
|---|--------|------|-------|
| 1 | Подсчёт и вывод статистики по CSV-файлу с сохранением отчёта | F# | `3_task_1_fsharp` |
| 2 | Слияние нескольких текстовых файлов с удалением дубликатов строк | Elixir | `3_task_2_elixir` |
| 3 | Поиск и замена подстроки в файлах с записью изменений в лог | Clojure | `3_task_3_clojure` |
| 4 | Чтение файла конфигурации и генерация файла-отчёта | D | `3_task_4_d` |

3.1 **F#.** Программа читает CSV-файл с числовыми данными (например, продажи: дата, товар, количество, цена). Считает по каждой числовой колонке: сумму, среднее, минимум, максимум, количество строк. Выводит таблицу в консоль и сохраняет её в отдельный текстовый файл-отчёт. Если файл не найден или формат битый — понятное сообщение об ошибке.

3.2 **Elixir.** Программа принимает список файлов, читает их построчно, объединяет содержимое, удаляет дубликаты строк (с сохранением порядка первого появления) и записывает результат в новый файл. Дополнительно печатает статистику: сколько строк было всего, сколько уникальных, сколько дубликатов удалено.

3.3 **Clojure.** Программа принимает путь к каталогу, искомую подстроку и замену. Рекурсивно обходит все .txt-файлы, в каждом считает число вхождений, выполняет замену и сохраняет файл. Все действия (файл, сколько заменено) пишутся в отдельный лог-файл с временными метками. В конце выводится сводка по каталогу.

3.4 **D.** Программа читает текстовый файл конфигурации в формате ключ = значение (построчно). Проверяет, что все обязательные ключи присутствуют, значения нужного типа (число/строка). Формирует отчёт: список параметров, ошибки валидации, значения по умолчанию для отсутствующих. Отчёт выводится в консоль и записывается в файл report.txt.

## Тема 4. Клиент-серверное взаимодействие

Папка: `4_client_server/`

| № | Задача | Язык | Ветка |
|---|--------|------|-------|
| 1 | Сервер-опросник: рассылает вопросы, собирает ответы, считает процент | Kotlin | `4_task_1_kotlin` |
| 2 | Сервер-калькулятор: клиент шлёт выражение, сервер считает | Swift | `4_task_2_swift` |
| 3 | Сервер общей доски объявлений (broadcast) | Erlang | `4_task_3_erlang` |
| 4 | Сервер файлового обмена: клиенты кладут и забирают файлы | Ruby | `4_task_4_ruby` |

4.1 **Kotlin.** TCP-сервер принимает несколько клиентов. Сервер хранит список вопросов (например, 5 штук с вариантами ответов). Каждому подключившемуся клиенту сервер последовательно задаёт вопросы, принимает ответ, проверяет его и ведёт счёт. В конце отправляет клиенту результат: сколько правильных, процент. Каждый клиент обслуживается в отдельном потоке или корутине. В консоль сервера пишется, кто подключился и сколько набрал.

4.2 **Swift.** TCP-сервер принимает подключения. Клиент отправляет арифметическое выражение, например (2 + 3) * 4 / (1 + 1). Сервер парсит его (рекурсивный спуск: выражение → терм → множитель → число/скобки), вычисляет результат и возвращает клиенту строку = 10.0. Если выражение некорректно — возвращает сообщение об ошибке. Каждый клиент обслуживается в отдельной очереди DispatchQueue. В консоль сервера пишется, кто сколько выражений посчитал.

4.3 **Erlang.** TCP-сервер на gen_tcp принимает подключения. На каждого клиента запускается отдельный процесс. Список клиентов держит процесс-диспетчер. Клиент отправляет POST <текст> — сервер добавляет объявление в общий список и рассылает всем подключённым клиентам обновлённую доску. Команда LIST возвращает текущий список, QUIT отключает клиента. В конце сервер печатает, сколько объявлений было добавлено за сессию.

4.4 **Ruby.** TCP-сервер принимает подключения. Клиент отправляет команды PUT <имя> <размер> (далее — содержимое файла), GET <имя>, LIST, QUIT. Сервер хранит файлы в отдельном каталоге, по PUT записывает, по GET отдаёт, по LIST возвращает список файлов с размерами. Каждый клиент обслуживается в отдельном потоке, доступ к каталогу — под Mutex.

## Тема 5. Конвертация данных из одного формата в другой

Папка: `5_convert/`

| № | Задача | Язык | Ветка |
|---|--------|------|-------|
| 1 | TSV → JSON | Perl | `5_task_1_perl` |
| 2 | JSON → YAML | Nim | `5_task_2_nim` |
| 3 | Fixed-width → CSV | Lua | `5_task_3_lua` |
| 4 | CSV → SQL INSERT | Objective-C | `5_task_4_objc` |

5.1 **Perl.** Программа читает TSV-файл (значения разделены табуляцией). Первая строка — заголовки. Каждая следующая строка превращается в JSON-объект: ключи — заголовки, значения — строки (числа определяются автоматически). JSON печатается с отступами. Спецсимволы (", \, \n, \t) экранируются вручную.

5.2 **Nim.** Программа читает JSON-файл с объектами, массивами, строками, числами, true/false/null. Строит дерево значений (свой вариант: SumType или классы). Затем рекурсивно печатает его в YAML с правильными отступами: объекты — key: value, массивы — - item, вложенность — отступ в 2 пробела. Строки экранируются при необходимости.

5.3 **Lua.** Программа читает текстовый файл фиксированной ширины: каждая строка — запись, поля занимают заранее заданные позиции (например, имя 0–20, возраст 20–23, город 23–40). Описание полей задаётся в начале файла или в отдельном конфиге. Программа извлекает поля, обрезает пробелы и пишет CSV с экранированием запятых и кавычек.

5.4 **Objective-C.** Программа читает CSV-файл (с кавычками и запятыми внутри полей), разбирает его в массив словарей. Затем генерирует SQL-файл с INSERT INTO table (col1, col2, ...) VALUES (...); для каждой строки. Строковые значения оборачиваются в одинарные кавычки, одинарные кавычки внутри экранируются удвоением. Числа вставляются без кавычек.
