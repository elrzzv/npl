# Задача 1.4 — параллельный обход дерева каталогов (Groovy)

Каталоги собираются в `ConcurrentLinkedQueue`. Рабочие потоки извлекают их
из очереди и подсчитывают файлы по расширениям через `ConcurrentHashMap`
и `AtomicLong`. Символические ссылки не обходятся.

Выводятся число каталогов и файлов, суммарный размер, топ-10 расширений,
время для одного и N потоков и результат сравнения всей статистики.
Число каталогов включает корневой. Регистр расширений не учитывается.

## Требования

* JDK 17+, переменная `JAVA_HOME` указывает на каталог JDK.
* Groovy, доступный командой `groovy` (проверено с 4.0.33).
* Дополнительные библиотеки не требуются.

## Запуск

Из корня репозитория в PowerShell:

```powershell
cd ./1_task_4_groovy
groovy GenerateDemo.groovy
groovy Main.groovy ./target/demo 4
```

`GenerateDemo.groovy` создаёт 1000 файлов в 50 подкаталогах `target/demo`.
Генератор использует seed `42` и не перезаписывает существующий каталог.
Для повторного обхода достаточно команды `Main.groovy`.

Первый аргумент — каталог, второй — положительное
число потоков. По умолчанию используется число доступных процессоров.
Во время сравнения содержимое каталога должно оставаться неизменным.
Ожидаемый итог: `Results match: OK`.

Время каждого варианта — медиана пяти замеров после трёх прогревочных обходов.
Порядок запуска вариантов чередуется.
Сбор каталогов и запуск потоков входят в замер, генерация файлов — нет.
